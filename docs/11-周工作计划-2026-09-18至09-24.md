# innoskill-hub 未来一周工作计划

制定日期：2026-09-18。计划周期：**2026-09-18 至 2026-09-24**，按接下来 7 个自然日安排；9 月 19–20 日为周末缓冲，不安排必须交付事项。本文是计划记录，所有后续任务当前均未据此标记为完成。

进度起点见 [工作记录](./10-工作记录.md)：旧版原型已有实现，新版只有两表模型评审稿，接口与业务代码尚未调整。任务编号沿用 [调整任务清单](./09-调整任务清单.md)。

## 一、本周目标

完成模型关键取舍的确认，统一需求、HTTP 接口、模块和后端设计，并推进新模型下的基础业务实现。在测试数据库、对象存储和身份接入条件及时到位的前提下，争取验证“上传一个技能 → 查询 / 搜索到它 → 申请下载 → 取得原包并留下下载记录”的完整流程。

| 目标层次 | 本周预期产物 | 完成依据 |
|---|---|---|
| 首要交付 | 一致的数据模型、DDL、四项功能需求、五个接口操作及后端流程 | 关键取舍有结论；文档之间字段、标识、行为一致 |
| 重点开发 | 外部业务库 / 对象存储接入，以及上传、列表、详情、搜索、下载的基础实现 | 有实际代码和针对关键行为的验证记录，不能仅完成接口文档 |
| 条件性交付 | 测试环境端到端验证和网关身份联调 | 真实环境有请求结果、数据库记录与对象大小 / 哈希核对证据 |
| 衔接准备 | 旧接口与调用方清单、存量样本导入方案、剩余问题清单 | 每项能明确保留、适配或待确认，不要求本周完成全量迁移 |

本周不新增版本、空间、审核、统计看板和前端展示功能。全量存量迁移、全部旧接口退役及生产切换另行安排；本周先盘点影响，不直接删除旧数据和调用入口。

- 盘点现有接口、页面和 InnoAgent 调用关系，优先识别新 UUID、包格式和下载方式对旧调用方的影响。

**预计产出：**模型评审结论记录、接入信息清单、第一版旧接口影响清单。对应 T0、T4 / T6 的准备工作。

**完成标准：**每项关键取舍有明确结论或明确待办；接入条件注明已具备 / 待提供；不把“提交评审”记为“评审通过”。当天的工作记录与周计划已在本会话形成，以上模型确认和外部对齐仍是待办。

### 9 月 19–20 日（周六、周日）：缓冲

不设置新的必须交付项。有反馈时可补充评审记录和整理样例包；无人反馈时不因此推定模型已确认。正式开发安排按后续工作日推进。

### 9 月 21 日（周一）：统一需求、HTTP 接口和后端流程

**计划工作：**

- 精简需求文档，只保留上传、下载、查询、搜索及必要说明。
- 重写上传、下载、列表、详情、搜索五个接口操作，逐项写清名称、方法、完整路径、参数类型 / 必填 / 枚举和响应。
- 统一用户 ID 来源、技能 ID、文件格式、分页、错误结果及重复请求的处理口径。
- 按业务职责重写模块和后端设计，用时序说明对象写入、元数据提交、失败恢复及下载记录，不把网关和现成存储写成自建模块。

**预计产出：**更新 `01`、`02`、`05`、`06`、`07` 文档，并与 `08`、`schema.sql` 保持一致。对应 T1–T3。

**完成标准：**用同一个样例技能能从上传请求推导到入库字段、查询响应和下载结果；不再出现旧版本路径、业务发布令牌或命名空间隔离要求与新模型冲突的情况。

### 9 月 22 日（周二）：实现业务库和对象存储接入

**计划工作：**

- 按实际数据库建立迁移文件及访问逻辑，在隔离测试库执行建表并验证主键、对象键唯一约束、下载外键等。
- 接入现成对象存储，实现写入、存在性检查、下载访问和必要的失败清理能力。
- 明确网关可信身份的读取方式，补充配置样例；测试凭据不写入工作记录或仓库。
- 新业务逻辑使用外部存储；规划与旧 SQLite / Git 链路的切换边界，避免开发中误删旧数据。

**预计产出：**数据库迁移及访问代码、对象存储接入代码、配置样例、连通性和约束验证记录。对应 T4。

**完成标准：**测试库可以写入及查询样例技能、记录下载申请；测试对象可写入和读取，并核对大小与哈希。如果测试服务未提供，只记录本地可验证结果，不标为真实服务接入完成。

### 9 月 23 日（周三）：实现上传、列表、详情和搜索

**计划工作：**

- 实现压缩包接收、名称简介提取、技能 ID 生成、文件属性计算及 OSS → 数据库的写入顺序。
- 处理上传校验失败、对象写入失败、数据库明确回滚和提交结果不明等情况。
- 实现按 ID 查询、列表分页及确认范围内的关键词搜索，避免返回内部对象键和操作人信息。
- 验证同名、重复上传约定、中文关键词、字面通配符及分页排序。

**预计产出：**可执行的上传及查询搜索接口、样例请求和关键验证结果。对应 T5 前半部分。

**完成标准：**成功上传后能查询和搜索到对应记录；失败上传不产生错误的可见记录；同名内容按已确认的规则处理。

### 9 月 24 日（周四）：实现下载记录，验证基本闭环并复盘

**计划工作：**

- 实现按技能 ID 定位对象、生成下载访问方式、记录可信用户 ID 后返回结果。
- 验证技能 / 对象不存在、身份上下文缺失、下载记录落库失败等情况；明确下载申请记录的含义。
- 在具备真实测试条件时跑通上传、查询、搜索、下载闭环，比对原包与下载包的大小及 SHA-256；验证另一实例也能读取共享数据。
- 根据接入结果补充新配置和联调说明，整理存量样本与旧 ID → 新 ID 映射方案。
- 更新工作记录和 T0–T7 状态，列明未完成内容、原因和下一周安排。

**预计产出：**下载接口和记录逻辑、闭环验证记录、接入说明增量、旧调用方 / 存量处理清单、周工作总结。对应 T5 后半部分及 T6 / T7 的首轮工作。

**完成标准：**使用真实测试服务完成的流程有证据；尚未完成的网关联调、兼容改造或迁移明确保留为待办，不把本地替身测试记为整体联调成功。
