# Innoskill 部署交接

> 给负责上线的人(或执行部署的 AI agent,如 Codex)。目标:把 Innoskill 跑在一台 Linux 服务器上,有域名、有 HTTPS、内容自动同步、重启不丢数据。
> 对应代码:`main`(2026-09-06)。命令全部在仓库根目录执行。

---

## 0. 最短路径(10 分钟)

**前提**:一台 Linux 服务器(2 vCPU / 2 GB 内存 / 20 GB 盘足够),装好 Docker 24+ 与 compose 插件(`docker compose version` 能跑),开放 80 / 443,能访问 github.com(拉内容源)。域名可选,先用 IP:8080 也能看效果。

```bash
# 1. 拿代码
git clone https://github.com/yuyue12111/innoskill.git && cd innoskill

# 2. 写 compose 层配置(这个 .env 不进镜像、不进 git)
cat > .env <<EOF
INNOSKILL_PUBLIC_URL=http://<服务器IP>:8080        # 上了域名+HTTPS 后改成 https://<域名>,改完要 restart
INNOSKILL_SERVICE_KEY=$(openssl rand -hex 24)      # 给 InnoAgent 后端用的服务密钥
INNOSKILL_SYNC_SECRET=$(openssl rand -hex 24)      # 手动/webhook 触发同步用
EOF

# 3. 构建并启动(首次约 3 分钟:拉基础镜像 + npm ci + next build;启动后再花 10 秒从 GitHub 拉内容)
docker compose up --build -d

# 4. 验收
sleep 20; curl -s localhost:8080/healthz
# 期望:{"ok":true,"lastSync":{"at":"…","sha":"…","ref":"main","skills":78,"presets":19}}
```

浏览器打开 `http://<服务器IP>:8080` 看到星图首页即成功。接下来做第 4.2 节的反向代理与 HTTPS,再把 `INNOSKILL_PUBLIC_URL` 改成正式地址。

国内服务器构建慢或失败,看第 4.3 节换镜像源。

## 1. 这是什么

Innoskill 是一个**单进程 Next.js 16 应用**,既出页面也出接口,不依赖任何外部数据库或中间件:

```
                ┌────────────────────── 容器 innoskill ──────────────────────┐
  浏览器 ──────►│ Next.js(node server.js :8080)                              │
  InnoAgent ───►│   ├─ 页面(纯 CSR)/ REST /api/v1/*  / bundle 协议 /index.json│
  inno-agent ──►│   ├─ SQLite(FTS5)  ← 索引、安装台账                         │
                │   └─ 调度器:启动同步一次 + 每 10 分钟 git fetch 内容源       │
                │ /data(卷)                                                   │
                │   ├─ innoskill.db(+ -wal/-shm)  SQLite                       │
                │   ├─ source/                    inno-agent-hub 的浅 clone     │
                │   └─ bundles/                   每个技能/预设的 tar.gz 缓存   │
                └──────────────────────────┬──────────────────────────────────┘
                                           │ git(出网)
                              github.com/Chloris-Blaxk/inno-agent-hub(内容真源)
```

- **内容不在这个仓库里**。技能、技能包、场景数据都在 GitHub 的 `inno-agent-hub` 仓库,Innoskill 定时拉取、解析、打包。合并一个技能 PR,最多 10 分钟后线上就有。
- **`/data` 里除了安装台账,全是可重建缓存**。删掉重启会自动重新拉取、重建索引。
- **只能跑一个实例**。SQLite 单文件 + 进程内调度器,不要开多副本。够用:几百个技能、读为主,单实例每秒几百请求没问题。

## 2. 运行要求

| 项 | 要求 |
|---|---|
| 系统 | Linux x86_64 或 arm64;macOS 本地也能跑 |
| Docker | 24+,带 `docker compose` 插件 |
| 资源 | 空闲内存 ~150 MB,峰值(同步打包时)~400 MB;镜像 ~450 MB;`/data` 首次 ~60 MB,随内容增长 |
| 端口 | 容器内 8080;对外由反向代理接 80/443 |
| 出网(构建时) | Docker Hub(拉 `node:24-alpine`)、npm registry |
| 出网(运行时) | `github.com`(clone / fetch 内容源)。**没有这条,目录会是空的** |
| 入网 | 80/443(反向代理);8080 不必对公网开放 |

不用 Docker 直接跑 Node 也可以,见第 4.4 节。

## 3. 配置项

全部是环境变量。用 compose 时,写在仓库根目录 `.env` 里的 **`INNOSKILL_*`** 会被 `docker-compose.yml` 映射成容器内变量(加前缀是为了不和本地 `next dev` 用的同名变量串味)。

| compose 变量(`.env`) | 容器内变量 | 默认 | 说明 |
|---|---|---|---|
| `INNOSKILL_PORT` | — | `8080` | 宿主机映射端口 |
| `INNOSKILL_PUBLIC_URL` | `PUBLIC_URL` | `http://localhost:8080` | **对外地址,必须和用户访问的 URL 一致**。tar.gz 下载地址、demo 图地址、`index.json` 里的链接都由它拼出来;填错了 inno-agent 拉包会 404 |
| `INNOSKILL_SERVICE_KEY` | `SERVICE_KEY` | 空 | InnoAgent 后端调 `/api/v1/users/*` 的密钥(请求头 `X-Innoskill-Key`)。**空 = 那组接口关闭(403)** |
| `INNOSKILL_SYNC_SECRET` | `SYNC_SECRET` | 空 | `POST /internal/sync` 的密钥(头 `X-Sync-Secret` 或 `?secret=`)。空 = 关闭,只剩定时同步 |
| `INNOSKILL_HUB_TOKEN` | `HUB_TOKEN` | 空 | 设了以后 bundle 协议(`/index.json`、`*.tar.gz`)要求 `Authorization: Bearer`。公开部署留空 |
| `INNOSKILL_SOURCE_REPO_URL` | `SOURCE_REPO_URL` | `https://github.com/Chloris-Blaxk/inno-agent-hub.git` | 内容源仓库。可换成镜像地址 |
| `INNOSKILL_SOURCE_REF` | `SOURCE_REF` | `main` | 分支 / tag |
| `INNOSKILL_SYNC_INTERVAL_MIN` | `SYNC_INTERVAL_MIN` | `10` | 定时同步间隔(分钟);`0` = 只在启动时同步 |
| `INNOSKILL_IMAGE` | — | `innoskill:dev` | 镜像名:tag,升级/回滚时用 |
| `INNOSKILL_NODE_IMAGE` | (构建参数) | `node:24-alpine` | 基础镜像,国内换镜像源 |
| `INNOSKILL_NPM_REGISTRY` | (构建参数) | `https://registry.npmjs.org` | npm 源,国内换镜像源 |

容器内固定值(Dockerfile 已设,不用管):`PORT=8080`、`HOSTNAME=0.0.0.0`、`DATA_DIR=/data`、`NODE_ENV=production`。

密钥生成:`openssl rand -hex 24`。改了 `.env` 要 `docker compose up -d` 让容器重建才生效(改 `INNOSKILL_NODE_IMAGE` / `NPM_REGISTRY` 要 `--build`)。

## 4. 部署方式

### 4.1 Docker compose(推荐)

第 0 节就是完整流程。补充几点:

- `docker compose up --build -d`:构建 + 后台启动;以后**代码更新必须带 `--build`**,只 `up` 会继续跑旧镜像
- `docker compose logs -f --tail 100`:看日志。启动成功的标志是两行:
  ```
  [sync] startup: main@<sha> skills=78 presets=19 packs=5 packed=<首次约 97,之后命中缓存为 0> (…ms)
  [innoskill] inno-agent contentHub → { "type": "bundle", "baseUrl": "…" }
  ```
- `restart: unless-stopped` 已配,宿主机重启会自动拉起
- 数据在命名卷 `innoskill-data`,`docker compose down` 不删卷;`down -v` 才删(会丢安装台账,见第 5 节)

### 4.2 反向代理 + HTTPS

8080 只在本机监听即可(把 compose 的 ports 改成 `"127.0.0.1:8080:8080"` 更稳妥),外面套一层代理。

**Caddy**(最省事,自动申请证书):

```
# /etc/caddy/Caddyfile
skills.example.com {
    reverse_proxy 127.0.0.1:8080
    encode gzip
}
```

**Nginx**:

```nginx
server {
    listen 443 ssl http2;
    server_name skills.example.com;
    ssl_certificate     /etc/letsencrypt/live/skills.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/skills.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 120s;      # 同步期间的首个请求可能慢一点
    }
}
server { listen 80; server_name skills.example.com; return 301 https://$host$request_uri; }
```

代理上好之后,**把 `.env` 的 `INNOSKILL_PUBLIC_URL` 改成 `https://skills.example.com`,`docker compose up -d`**。不改的话页面能开,但 tar.gz 和 demo 图的链接还是旧地址。

### 4.3 国内服务器

三处可能被网络卡住,都有绕法:

| 卡在哪 | 现象 | 解法 |
|---|---|---|
| 拉基础镜像 | `docker compose build` 卡在 `FROM node:24-alpine` | `.env` 加 `INNOSKILL_NODE_IMAGE=docker.m.daocloud.io/library/node:24-alpine`(或给 Docker 配 `registry-mirrors`) |
| npm ci | 构建卡在 `npm ci` | `.env` 加 `INNOSKILL_NPM_REGISTRY=https://registry.npmmirror.com` |
| 运行时 clone GitHub | 日志 `[sync] startup failed: git clone … failed`,healthz 的 `lastSync` 为 `null`,页面空 | 见下 |

内容源拉不到 GitHub 的两个办法:

1. **换镜像仓库**:把 `inno-agent-hub` 镜像到 Gitee / 自建 GitLab(设置里开自动同步),`INNOSKILL_SOURCE_REPO_URL=https://gitee.com/<org>/inno-agent-hub.git`
2. **宿主机代拉**:服务器上另起 cron 用能出网的方式同步仓库到 `/srv/inno-agent-hub`,然后在 compose 里挂进去并让 Innoskill 直接读目录(不做 git):
   ```yaml
   # docker-compose.override.yml
   services:
     innoskill:
       environment: { SOURCE_LOCAL_DIR: /content }
       volumes: [ "/srv/inno-agent-hub:/content:ro" ]
   ```
   这时定时同步会重新扫描目录,cron 拉完就生效。

Next 构建**不依赖任何外网字体或 CDN**,构建期间只需要 npm registry。

### 4.4 不用 Docker,直接跑 Node

需要 Node ≥ 24(`node:sqlite` 内置)、git。

```bash
git clone https://github.com/yuyue12111/innoskill.git && cd innoskill
npm ci && npm run build
# 环境变量用容器内的名字(不带 INNOSKILL_ 前缀)
export PORT=8080 HOSTNAME=0.0.0.0 DATA_DIR=/var/lib/innoskill \
       PUBLIC_URL=https://skills.example.com SERVICE_KEY=… SYNC_SECRET=…
npm start        # = next start
```

systemd 单元示意(`/etc/systemd/system/innoskill.service`):

```ini
[Unit]
Description=Innoskill
After=network-online.target
[Service]
WorkingDirectory=/opt/innoskill
EnvironmentFile=/etc/innoskill.env
ExecStart=/usr/bin/npm start
Restart=always
User=innoskill
[Install]
WantedBy=multi-user.target
```

## 5. 数据与备份

`/data`(卷 `innoskill-data`)里:

| 路径 | 是什么 | 能否重建 |
|---|---|---|
| `source/` | 内容源仓库浅 clone | 能,删了自动重拉 |
| `bundles/` | 每个技能 / 预设的 tar.gz | 能,同步时重打 |
| `innoskill.db` 里 `skill` `skill_fts` `preset` `pack*` `sync_run` `kv` | 索引 | 能 |
| `innoskill.db` 里 **`user_install`、`skill_stat`** | **用户安装台账、安装/浏览计数** | **不能** —— 这是唯一真状态 |

所以:**第一期只做展示时不用备份;接了 InnoAgent 的一键添加之后要备份 `innoskill.db`**。

备份(SQLite 在线备份,不用停服):

```bash
docker compose exec innoskill sh -c 'cp /data/innoskill.db /data/innoskill.db.bak && sync' \
  && docker compose cp innoskill:/data/innoskill.db.bak ./backup/innoskill-$(date +%F).db
```

更稳的做法是宿主机装 `sqlite3` 后 `sqlite3 <卷路径>/innoskill.db ".backup backup.db"`。恢复:停容器,把文件放回卷里(连同删除 `-wal` / `-shm`),启动。

要迁移服务器:备份 `.env` + `innoskill.db` 两样就够,其余重建。

## 6. 日常运维

| 操作 | 命令 |
|---|---|
| 看状态 | `curl -s localhost:8080/healthz`(`lastSync` 有值且 `skills>0` 即正常) |
| 看日志 | `docker compose logs -f --tail 200` |
| 手动触发同步 | `curl -X POST -H "X-Sync-Secret: $SECRET" localhost:8080/internal/sync`;看最近几次:`curl -H "X-Sync-Secret: $SECRET" localhost:8080/internal/sync/runs` |
| 升级代码 | `git pull && docker compose up --build -d`(会短暂中断几秒) |
| 回滚 | 构建前先打标:`docker tag innoskill:dev innoskill:prev`;回滚 `INNOSKILL_IMAGE=innoskill:prev docker compose up -d --no-build` |
| 改配置 | 改 `.env` 后 `docker compose up -d` |
| 清空重建 | `docker compose down -v && docker compose up -d`(**丢安装台账**,先备份) |

**GitHub webhook(可选,让内容合并后立即生效)**:在 `inno-agent-hub` 仓库 Settings → Webhooks → Add:
- Payload URL:`https://skills.example.com/internal/sync?secret=<INNOSKILL_SYNC_SECRET>`
- Content type:随意;Events:Just the push event
不配也行,定时同步每 10 分钟一次。

## 7. 上线验收清单

按顺序跑,每条都应符合预期:

```bash
H=https://skills.example.com        # 或 http://<IP>:8080

curl -s $H/healthz                                   # lastSync.skills == 78(以当时内容为准)
curl -s $H/index.json | head -c 300                  # count.skills / presets 有值
curl -sI $H/skills/k12-lesson-planning.tar.gz | head -3   # 200, application/gzip
curl -s $H/api/v1/meta | head -c 400                 # subjects / kinds / scenarios 有值
curl -s -G --data-urlencode "q=备课" $H/api/v1/skills | head -c 300   # total > 0
curl -s -o /dev/null -w "%{http_code}\n" $H/api/v1/users/t/installs  # 401(SERVICE_KEY 已配)或 403(没配)
curl -s -o /dev/null -w "%{http_code}\n" $H/ ; curl -s -o /dev/null -w "%{http_code}\n" $H/skills   # 200 200
```

浏览器:首页星图(滚一下鼠标进入)、`/skills` 列表能搜索筛选、点开任一技能详情能看 SKILL.md、`/presets` 有卡片。手机上也开一次。

最后确认 `index.json` 里 demo 地址和详情页 `bundleUrl` 的域名是正式域名,不是 localhost —— 不是就回第 4.2 节改 `PUBLIC_URL`。

## 9. 安全与已知限制

- 只读接口全部匿名可访问,这是设计如此(公开目录);写接口(`/api/v1/users/*`)靠服务密钥,`/internal/*` 靠同步密钥,**两把密钥都别提交进 git**(`.env` 已在 `.gitignore` 和 `.dockerignore`)
- 没有限流;放在 Nginx / Caddy 后面按需加
- 没有 CORS 头:浏览器只应访问同域页面,InnoAgent 是服务端到服务端调用,不需要
- 单实例;需要高可用再谈(换 Postgres + 外置对象存储,见 `docs/02-模块划分.md`)
- HTTPS 由反向代理负责,应用本身只讲 HTTP

## 10. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `healthz` 的 `lastSync: null`,页面空,日志 `startup failed: git clone` | 容器出不了网到 github.com | 第 4.3 节换源;或先 `SOURCE_LOCAL_DIR` 挂本地目录 |
| 页面能开,点技能 demo 图 / 下载 tar.gz 404,或链接指向 localhost | `PUBLIC_URL` 没改成正式地址 | 改 `.env`,`docker compose up -d` |
| `/api/v1/users/*` 返回 403 | `SERVICE_KEY` 没配 | `.env` 加 `INNOSKILL_SERVICE_KEY` |
| 返回 401 | 密钥不匹配 | 核对请求头 `X-Innoskill-Key` |
| 内容合并了线上没更新 | 还没到定时点;或同步失败 | 手动 `POST /internal/sync`;看 `/internal/sync/runs` 的 `status` / `message` |
| 构建卡住 | 拉镜像 / npm 慢 | 第 4.3 节 |
| 更新代码后行为没变 | 只 `up` 没 `--build` | `docker compose up --build -d` |
| 端口被占 | 8080 已有服务 | `.env` 加 `INNOSKILL_PORT=18080` |
| 容器反复重启 | 看 `docker compose logs`;常见是 `/data` 权限或磁盘满 | 修权限 / 清盘 |

日志里 `[sync]` 开头的是同步,`[innoskill]` 开头的是启动信息;Next.js 自身的请求日志默认不打。
