## 4. 旧方案删减清单

| 旧方案内容 | 新方案处理 |
|---|---|
| namespace / 多租户 / 三档可见性 / 用户空间 | 当前需求不采用；用户 ID 只用于操作记录 |
| 发布令牌、服务密钥、SSO / OAuth 模块 | 认证权限归网关，业务只消费可信身份 |
| version / changelog / latest / resolve / yank / 审核 / 版本标签 | 本期全部去除，不先预留状态和接口 |
| `skill_version`、`skill_file` | 一包一条技能记录；不做逐文件预览和历史版本 |
| 独立搜索表、分面、高亮、向量搜索、复杂筛选和排行 | 先实现名称简介的关键词搜索和分页 |
| 安装台账、统计快照、通用事件流、统计定时聚合 | 不进入新核心模型，只保留下载申请记录 |
| 技能组合包、预设、星图、精选等展示需求 | 不放进本次四项基础功能；已有码另做去留与兼容盘点 |
| Git 作为技能源、定时同步、导入器平台 | OSS + 业务库保存数据；有需要才做一次性导入 |
| 自建 PG、S3 / MinIO、独立缓存、队列等基础设施 | 使用团队现成服务，只实现业务接入 |

## 5. 后续验证重点

- 上传得到 ID 后，另一服务实例能查到同一技能并下载到原包；比对大小和 SHA-256。
- OSS 写入失败不出现技能；数据库明确回滚能清理对象，提交结果不明时不误删已入库对象。
- 同名技能不冲突、按 ID 下载正确；对重试行为按模型定稿后的约定验证。
- 列表与搜索公开；上传下载记录可信用户，伪造身份不能穿过网关；不返回内部对象键和用户流水。
- 中文关键词、`%` / `_` 等字面输入及分页可用；用实际数据量测搜索，不沿用旧文档未验证的性能承诺。
- 下载记录表示受理申请；对象不存在、记录落库失败或地址生成失败都不返回成功。
- 存量导入核对数量、描述、对象大小和哈希；现有安装记录不误转为下载记录。
- 旧调用方按确定的去留方案联调；重启实例不需要重新拉 Git，也不需要重建本地数据库。

本轮改动范围：新增模型和任务清单、替换设计 DDL、为旧文档标注待调整状态。T1–T7 的运行时代码和联调尚未完成；没有对现有数据库、对象存储或旧数据执行修改。
