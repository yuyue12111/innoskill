# Innoskill 模块划分

> 回答"新代码往哪放"。iflytek/skillhub 是 Java 多模块(app / auth / domain / infra / search / storage / notification),那是给带 RBAC、对象存储、通知的企业注册中心用的分法。我们只借它**分层的思路**,不照搬目录 —— 单进程 Next.js 里再切七个包只会多出七份样板。

## 各层职责与依赖方向

| 层 | 目录 | 只做 | 可以 import | 不许 |
|---|---|---|---|---|
| 接口 | `app/**/route.ts` | 解析 query / params、调 auth、调 catalog / sync,返回 `Response` | `lib/server/*` | 直接写 SQL;写业务逻辑 |
| 读模型 | `lib/server/catalog.ts` | 所有 SELECT、DTO 组装(`toSummary`)、路径安全(`safeJoin`)、文件流响应 | `db`、`config`、`sync/pack`(取包路径) | 写库;碰 `next/*` |
| 星图领域 | `lib/server/map/` | riso 图块生成、布局松弛、按同步版本缓存 | `catalog`、`db`、`config` | 碰 HTTP |
| 写模型 | `lib/server/sync/` | `git.ts` 拿源;`parse.ts` 解析 SKILL.md / README / scenarios / preset;`pack.ts` 打 tar.gz;`run.ts` 编排 + 事务 | `db`、`config` | 被 route 直接调(只允许 `runSync` / `isSyncRunning`) |
| 安装与统计 | `lib/server/installs.ts` | `user_install` / `skill_stat` 的读写:幂等安装、卸载、浏览计数、重算安装人数 | `db`、`catalog`(复用 summary SQL) | 被匿名路由调用写操作(写接口一律过 `auth/service`) |
| 存储 | `lib/server/db.ts` | 建表、单例、kv | `config` | 业务判断 |
| 鉴权 | `lib/server/auth/` | `bundle.ts` bundle 协议 Bearer;`internal.ts` 同步密钥;`service.ts` InnoAgent 服务密钥 `X-Innoskill-Key` | `config`、`http` | 用户概念(IAM 归 InnoAgent,`user_id` 只是字符串,这里只校验凭据) |
| 调度 | `lib/server/scheduler.ts` + `instrumentation.ts` | 进程启动同步一次、挂定时器 | `sync/run`、`db` | — |
| 前端数据 | `lib/api.ts`、`lib/types.ts` | SWR hooks、API 类型、配色常量 | 无服务端代码 | import `lib/server/**`(会把 node 模块打进浏览器) |
| 页面 | `app/**/page.tsx`、`components/**` | 全部 `"use client"`,只通过 `lib/api` 拿数据 | `lib/api`、`lib/types`、`components/ui` | 直接 `fetch`;import `lib/server/**` |

三条铁律:

1. **数据流单向**:`sync` 写 → `db` → `catalog` 读 → `route` 出。路由永远不写库,同步永远不出 HTTP。
2. **`lib/server/**` 是 Node 专属**,里面用 `node:fs` / `node:sqlite` / `child_process` 都可以;`lib/api.ts`、`lib/types.ts`、`components/**` 绝不 import 它。类型要共享就抄到 `lib/types.ts`(见 `SkillSummary` 两份定义,故意的)。
3. **内容真源在仓库外**:`runtime/` 下的 SQLite、tar.gz、源 clone 全是可重建缓存,删了重启即恢复;Innoskill 自己不持有任何技能的主副本。

## 与 iflytek/skillhub 的对照

| iflytek 模块 | 我们对应 | 说明 |
|---|---|---|
| `skillhub-app`(Controller) | `app/**/route.ts` | 同样是薄接口层 |
| `skillhub-domain` | `lib/server/catalog.ts` + `lib/types.ts` + `lib/server/map/` | 没有实体 / 仓储抽象,SQLite 行就是模型 |
| `skillhub-infra`(JPA / Flyway) | `lib/server/db.ts`(`CREATE TABLE IF NOT EXISTS`) | 表结构变更直接改 SCHEMA;真需要迁移时再引 Drizzle |
| `skillhub-search`(Postgres 全文) | `skill_fts`(FTS5 trigram) | 在 catalog 里,不单独成层 |
| `skillhub-storage`(S3 / MinIO) | `lib/server/sync/pack.ts` + `runtime/bundles/` | 本地文件系统;要上 OSS 时只改 `bundlePath` / `fileResponse` |
| `skillhub-auth`(OAuth2 / SSO) | `lib/server/auth/`(两个函数) | 第一期没有用户 |
| `skillhub-notification` | 无 | 不需要 |
| `web`(React) | `app/**/page.tsx` + `components/` | 同一进程,不单独部署 |

## 第二期(已落地)是怎么加的

- **用户安装记录**:`lib/server/installs.ts` + `app/api/v1/users/[uid]/installs/**`;`auth/service.ts` 校验 InnoAgent 服务密钥。没有新层。
- **技能包**:内容在 hub 仓库 `skill-library/packs.json`,`sync/parse.ts` 多解析一个文件,`catalog.ts` 多了 `listPacks / getPack / packSkillIds / packsOfSkill`。没有新层。
- **店面维度**(subject / kind):不加列,`json_extract(frontmatter_json)`。

## 再往后
- **切 Postgres / OSS**:只动 `db.ts` 与 `pack.ts` / `fileResponse`,上层不感知。
