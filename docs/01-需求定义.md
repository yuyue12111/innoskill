# Innoskill 需求定义(v0.2,2026-09-06)

> 本文是 Innoskill 平台的需求与技术方案基线。已确认项来自 2026-09-06 的讨论;"待确认"段落是仍需拍板的点。改动请直接改本文并升版本号。

## 1. 定位

**Innoskill 是一个技能的 hub,同时也是展示站。** 用途是让人挑选技能,并向 Agent 运行时供货。

- 名字:**Innoskill**(不叫 SkillHub)
- 受众:教育场景的使用者(老师 / 学生 / 研究者)和 InnoAgent 产品团队
- 定位:**严选**,不是海量爬取。质量由收录流程保证,不靠 AI 打分

## 2. 已确认的决策

| # | 决策 | 结论 |
|---|---|---|
| 1 | CLI | **第一期不做** |
| 2 | 运行时 | InnoAgent 基于 Pi SDK(`@earendil-works/pi-coding-agent`),技能格式为 SKILL.md(frontmatter + 正文 + 附属文件),与当前 `skill-library` 一致 |
| 3 | 用户与安装记录 | **第一期不做**,只预留数据模型。IAM 完全不在 Innoskill 范围内:线上 InnoAgent 部署已有,与本平台业务逻辑无关 |
| 4 | 付费 | **不做**,数据模型不预留 |
| 5 | 技能怎么进来 | **只走 GitHub PR 进 `inno-agent-hub`**,Innoskill 从仓库同步。不做网页上传发布、不做审核后台 |
| 6 | 规模 | 严选,现 78 个,预期数百 |
| 7 | 技术栈 | **Next.js 一把梭哈**:前端 Next.js + shadcn/ui,纯 CSR;后端用 Next Route Handlers + `node:sqlite`。iflytek/skillhub 只作参考。见第 4 节 |

## 3. 相关系统与约束

### 3.1 inno-agent 开源版(hhyqhh/inno-agent)

- Node ≥ 20 + TypeScript;后端是原生 `http.createServer`,无框架;前端 React 19 + Tailwind 4 + Vite;本地状态 SQLite(FTS5)
- **单用户、无账号体系**。"安装技能" = 把技能目录解压到本机 `skills/`
- **已内置 Content Hub 客户端**(`src/content-source/`),两种传输:
  - `github`:直接读 GitHub 仓库(当前默认指向 `Chloris-Blaxk/inno-agent-hub`)
  - `bundle`:自托管服务,协议见 5.1。**Innoskill 只要实现这个协议,inno-agent 零改动**
- 它的 Web UI 技能库页只用到:`name`、`description`、`category`、`installed`

### 3.2 InnoAgent 线上多用户版(innoagent.tech)

- 已上线;前端是 Vite 构建的 SPA,网关是 Kong 3.8;后端语言与 IAM 实现**未知**(自建)
- 设计稿(v4 `skills.html`)中的「技能仓库」页含:学科 tab、类型标签(技能包 / 课件生成 / 教学设计 / 课堂分析 / 评价测评 / 教研科研)、「学科技能包」卡片(含多个技能)、一键添加、安装人数、我的技能、安装记录、含付费标记
- 这些是**第二期**的客户端需求,第一期只保证数据模型能长出来

### 3.3 inno-agent-hub(内容源)

- `skill-library/<id>/SKILL.md` + `skill-library/README.md`(目录表:类型 / 通过验证 / 一句话 / 引用 / 效果 / 分组)+ `skill-library/assets/<id>/demo.gif`
- `workspace-templates/<id>/preset.json` + `agent.md` + `.skills/`
- 已有静态展示站(`docs/`,星图 + 卡片页),由 `scripts/build_skills_site.py` 生成;场景归属在 `scripts/skill_scenarios.py`
- **这是唯一真源。** Innoskill 不持有任何技能内容的"主副本"

### 3.4 iflytek/skillhub(参考)

- Java 21 / Spring Boot 多模块 + Postgres + Redis + MinIO,React 19;OAuth2/OIDC + 本地账号,预留企业 SSO 接入点(`/api/v1/auth/session/bootstrap`、`/api/v1/auth/direct/login`)
- 值得借的:域模型(`docs/02-domain-model.md`)、技能包协议(`docs/07-skill-protocol.md`,与 SKILL.md 互操作)、SSO 接入设计(`docs/11`、`docs/12`)
- 不借的:命名空间 / RBAC / 上传发布 / 版本 tag / 审计日志,这些服务于"企业内部多团队发布",与严选 + GitHub PR 的模式相反

## 4. 技术方案:Next.js 一把梭哈

### 4.1 为什么不 fork iflytek/skillhub

1. 它 80% 的功能(命名空间、RBAC、上传发布、审核提升、审计)是我们第一期明确不要的,fork 之后是在删功能,不是加
2. Java + Postgres + Redis + MinIO 四件套对一个几百技能、只读为主的服务是过度设计,运维成本高
3. 团队栈是 TypeScript(inno-agent 开源版与线上版前端都是),Java 会成为只有少数人能改的孤岛
4. 它的下载协议(按版本 zip)与 inno-agent 的 bundle 协议不同,无论如何都要写适配层

### 4.2 选型

| 层 | 选择 | 理由 |
|---|---|---|
| 框架 | **Next.js 16(App Router)**,一个进程同时出页面和 API | 一个仓库、一个进程、一个容器、一种心智模型 |
| 页面 | React 19 + shadcn/ui + Tailwind 4,**全部客户端渲染**(`"use client"` + 浏览器 fetch 自己的 API) | 不做 SSR;Next 服务端只负责 API 和 tar 包 |
| API | Route Handlers(`app/**/route.ts`),Node runtime | 直接用 Web `Request`/`Response` |
| 数据库 | SQLite(**Node 内置 `node:sqlite`**)+ FTS5(trigram 分词,中英文都能子串搜) | 零原生依赖;几百技能只读为主,Postgres 是过度设计 |
| 后台同步 | `instrumentation.ts` 启动时同步一次 + `setInterval` 定时;`POST /internal/sync` 供 webhook | Next 没有调度器,这是"顺着它脾气"的做法;单实例没问题 |
| 打包 | `git` 浅 clone/fetch + `tar`(npm 包) | 内容哈希没变就不重打 |
| 部署 | `output: "standalone"` 单容器 Docker compose | 本地 `docker compose up` 拉起 |

已知的取舍:`node:sqlite` 与 `tar` 只能跑在 Node runtime(不能 Edge);`node:sqlite` 用 `process.getBuiltinModule` 获取,绕开 Turbopack 对新内置模块的解析。

### 4.3 仓库结构

```
innoskill/
├── app/
│   ├── (页面)  page.tsx / skills/page.tsx / skill/[id]/page.tsx / presets/page.tsx / preset/[id]/page.tsx
│   ├── index.json/route.ts            bundle 协议:目录
│   ├── skills/[file]/route.ts         bundle 协议:{id}.tar.gz
│   ├── presets/[file]/route.ts
│   ├── api/v1/**/route.ts             REST
│   ├── assets/[...path]/route.ts      演示素材
│   ├── healthz/route.ts
│   └── internal/sync/route.ts         webhook
├── lib/server/                        config / db / catalog(查询) / sync(git·parse·pack·run)/ scheduler
├── components/                        页面组件(shadcn 在 components/ui)
├── instrumentation.ts                 启动同步 + 定时器
├── docs/  docker/  docker-compose.yml
```

页面路径与 bundle 协议路径不能撞:`/skills/<id>.tar.gz` 归协议,所以技能详情页在 `/skill/[id]`(单数),预设详情在 `/preset/[id]`。

## 5. 第一期范围(MVP)

### 5.1 供货:bundle 协议(必须,零改动接 inno-agent)

```
GET /index.json
  → { "skills": [ { id, name, description, category, tagline, group, refUrl, demo, scenario, example, verified } ],
      "presets": [ { id, name, description, icon } ] }
GET /skills/{id}.tar.gz      技能目录打包,顶层目录名 = id
GET /presets/{id}.tar.gz     预设目录打包,顶层目录名 = id
```

- 可选 `Authorization: Bearer <token>`(私有部署开关)
- `id` 必须是单段安全名(无 `/`、`\`、`..`),与目录名一致
- inno-agent 只读 `id / name / description / category`,其余字段是给我们自己前端和未来客户端的,多给不影响
- 参考实现:`inno-agent/scripts/content-hub-server/server.mjs`

### 5.2 同步(必须)

- 源:`Chloris-Blaxk/inno-agent-hub@main`(可配置 owner / repo / ref / 路径)
- 触发:启动时一次 + 每 N 分钟 + `POST /internal/sync`(webhook,带密钥)
- 解析:`SKILL.md` frontmatter(name / description / category)、`README.md` 目录表、`assets/`、`workspace-templates/*/preset.json`、以及 `scripts/skill_scenarios.py` 里的场景与示例(第一期可先把它转成 JSON 放进 hub 仓库,Innoskill 只读 JSON)
- 产物:SQLite 索引 + 每个技能 / 预设的 tar.gz 缓存 + demo 静态文件
- 同步失败不影响线上服务,继续用上一版索引

### 5.3 REST(必须,给自己前端和未来 InnoAgent 用)

```
GET /api/v1/skills?q=&category=&scenario=&page=&size=    列表 / 全文搜索(FTS5)
GET /api/v1/skills/{id}                                 详情:frontmatter 全量 + README 表字段 + 文件清单
GET /api/v1/skills/{id}/file?path=SKILL.md              读单个文件(渲染详情页正文)
GET /api/v1/presets  /api/v1/presets/{id}
GET /api/v1/meta                                        分类、场景、数量、最近同步时间
GET /healthz
```

统一响应 `{ code, msg, data }`;匿名可读。

### 5.4 前端(必须,Next.js + shadcn,纯 CSR)

- `/` 星图首页:**展示位,不是全集**。只放 `scenarios.json` 里 `featured` 列出的精选技能(MVP 展示,fancy 设计),全部技能走 `/skills`。riso 图块与布局算法移植到 TS,由 `/api/v1/map` 提供
- `/skills` 全部技能页(搜索 + 分类 / 场景筛选)
- `/skill/[id]` **技能详情页**(现在没有):正文渲染、文件树、出处、演示、示例输入、"在 InnoAgent 中使用"(第一期只展示配置说明)
- `/presets`、`/preset/[id]` 预设(工作区模板)列表与详情
- 移动端可用

### 5.5 非功能

- 单容器部署,`docker compose up` 即跑
- 索引与包全部可由源仓库重建,服务本身无需备份
- 中文优先,预留 i18n

## 6. 数据模型

第一期落库的表(SQLite):

- `skill`(id PK, name, description, category, tagline, group, type, verified, ref_text, ref_url, demo_path, scenario, also_json, example, frontmatter_json, files_json, content_hash, synced_at)
- `skill_fts`(FTS5:name, description, tagline, body)
- `preset`(id PK, name, description, icon, files_json, content_hash, synced_at)
- `sync_run`(id, started_at, finished_at, source_ref, commit_sha, status, message)

第二期预留(建表但不启用):

- `pack`(技能包:id, name, description, subject, curated_by)+ `pack_skill`(pack_id, skill_id, order)
- `user_install`(user_id, skill_id, installed_at, uninstalled_at)—— `user_id` 来自 InnoAgent IAM,为字符串,不做外键
- `skill_stat`(skill_id, install_count, view_count)

## 7. 与 inno-agent 联调

1. `innoskill` 起在 `:8080`
2. `inno-agent/runtime/config/config.json`:`"contentHub": { "type": "bundle", "baseUrl": "http://localhost:8080", "token": "" }`
3. 重启 inno-agent 后端,`curl localhost:3000/api/skill-library` 应列出 Innoskill 的技能;Web UI 技能库页可导入

## 8. 第二期(接线上多用户版 InnoAgent)

- **IAM 不在范围内**:线上 InnoAgent 部署已具备,由它在调用 Innoskill 时带上用户标识即可;Innoskill 只按字符串 `user_id` 记录
- 安装 / 卸载记录、我的技能、安装人数
- 学科技能包(pack):严选组合,`subject` 维度按设计稿(语文 / 数学 / … / 跨学科)
- 设计稿里的类型标签(课件生成 / 教学设计 / …)映射为新的分类维度,需与现有 `category` 协调
