## 1. 定位

**innoskill-hub 是面向教育场景的技能注册中心(registry)**:自己存储技能、按租户隔离、让技能制作平台直接发布、让 InnoAgent 直接消费,同时对人提供浏览与搜索的独立站。

一句话:**制作平台往里发,InnoAgent 从里取,人来这里挑。**

为什么改:v0.4 把 GitHub 仓库当唯一真源、平台只做同步展示,满足不了"制作平台发布"和"租户隔离"两个核心诉求。

---

## 2. 角色与系统

| 角色 / 系统 | 是谁 | 对本平台要什么 |
|---|---|---|
| 技能制作平台 | 独立系统(在建),用户在里面做技能 | 服务端调用发布接口,把技能推上来;自己保留源文件 |
| InnoAgent 线上版(innoagent.tech) | 多用户 agent 产品,TS 栈,自建登录 | 拉技能目录与搜索、按租户看到该看的、下载技能、记用户安装台账 |
| inno-agent 开源版 | 单用户 agent,内置 bundle 协议客户端 | 现有协议不变,改个配置就能用 |
| 独立站访客 | 老师 / 学生 / 研究者 | 按场景挑技能,看示例、看效果、看包里有什么 |
| 平台运维 | 我们 | 部署、发令牌、导入官方库、看健康 |

**不在本平台内**:用户注册登录、租户管理(登录体系负责,平台只拿到 `namespace` 字符串)。

## 3. 术语

| 词            | 含义                                                               |
| ------------ | ---------------------------------------------------------------- |
| skill 技能     | 一个目录:`SKILL.md`(frontmatter + 正文)+ 附属文件,Pi SDK / Agent Skills 格式 |
| namespace    | 租户标识,也是技能坐标前缀;`official` 保留给平台官方库                                |
| 坐标           | `namespace/slug`,全局唯一;`slug` = 目录名 = 安装后目录名                      |
| version      | 语义化版本,发布后不可变;`latest` = 最新已发布版                                   |
| artifact     | 某版本的 tar.gz,按 sha256 内容寻址                                        |
| visibility   | `public` 所有人 / `tenant` 同租户 / `private` 仅发布方                     |
| pack 技能包     | 严选的技能组合                                                          |
| preset 工作区预设 | inno-agent 简单模式用的工作区模板                                           |
| install 安装记录 | (user_id, skill, version) 一条,卸载只打时间戳                             |

## 5. 功能需求

编号规则:P 发布、C 消费、W 浏览、O 运营。每条附验收要点。

### 5.1 发布(制作平台)

| # | 需求 | 验收要点 |
|---|---|---|
| P1 | 上传一个技能版本(tar.gz / zip,≤ 30 MB) | 201 返回版本、sha256、下载地址;同版本同内容重传 200;同版本不同内容 409 |
| P2 | 服务端校验:根目录有 `SKILL.md`;frontmatter `name` = slug,`description / category / subject / kind` 必填且在取值表内;禁 `..`、绝对路径、符号链接、可执行二进制 | 失败 400,一次列出全部问题 |
| P3 | 版本不可变;`latest` 自动指向最新已发布版 | 无覆盖发布接口;yank 后 `latest` 回退到上一个已发布版 |
| P4 | 改可见性、标记弃用、下架某版本 | 下架版本不再被 resolve / 搜索命中,直链 410 |
| P5 | 发布凭证是 Bearer 令牌,代表制作平台系统 | 无令牌 401;令牌只能操作路径里的 namespace 由制作平台自证 |
| P6 | slug 首次出现自动建技能(与 namespace),默认可见性 `tenant` ⚠️ | 不需要预先建坐标 |

### 5.2 消费(InnoAgent 线上版 / 开源版)

| # | 需求 | 验收要点 |
|---|---|---|
| C1 | 目录:列表、详情、版本列表,按 `namespace / category / subject / kind / scenario / pack / featured` 过滤,按 `recent / downloads / installs / name` 排序 | 分页;带租户头时能看到本租户 `tenant` 技能,匿名只见 `public` |
| C2 | 搜索:`q` 全文,中英文,可与过滤组合,返回相关度、`tagline` 高亮、结果集内分面 | w 级技能 p95 < 300 ms |
| C3 | resolve:按 `version / tag / hash` 解析,`hash` 命中返回 `matched: true` | agent 只用一个请求判断要不要更新 |
| C4 | 下载:返回 10 分钟有效的临时 OSS 地址;包不经过后端;`?redirect=1` 302 | 桶私有读;地址按 sha256 内容寻址 |
| C5 | 安装台账(已有):安装 / 卸载 / 我的技能 / 历史,记到版本 | 幂等;卸载保留历史;安装人数 = 未卸载去重用户 |
| C6 | 统计:下载 / 安装 / 浏览,读接口只读快照 | 计数经事件流水异步聚合,多实例不冲突 |
| C7 | 兼容开源版:`/index.json`、`/skills/{slug}.tar.gz`、`/presets/{id}.tar.gz` | inno-agent 零改动;`.tar.gz` 302 到临时地址 |
| C8 | 分面元数据 `/meta`:namespace / category / subject / kind / scenario 的取值与计数 | 下游 tab 不写死 |

### 5.3 浏览(独立站)

| # | 需求 | 验收要点 |
|---|---|---|
| W1 | 星图首页只展示精选(`featured`),按五个场景成星系 | 已有,数据源切到新接口 |
| W2 | 列表:搜索 + 分类 / 场景 / 学科 / 用途 / 精选 / 技能包筛选 | 已有 |
| W3 | 详情:正文渲染、文件树、示例输入、所属技能包、在用人数、版本列表 | 版本列表为新增 |
| W4 | 技能包列表与包内技能 | 已有 |
| W5 | 匿名只见 `public`;独立站不做登录 | — |

### 5.4 运营与运维

| # | 需求 | 验收要点 |
|---|---|---|
| O1 | 官方库导入器:从 GitHub `inno-agent-hub` 把技能作为 `official` 的版本走同一条发布流水 | 内容没变则跳过;可定时 / 手动触发 |
| O2 | 后台任务:统计聚合(每分钟)、孤儿对象清理(每天) | 有运行记录 |
| O3 | 健康检查:PG、OSS 连通性,最近导入,技能 / 预设 / 包计数 | `/healthz` |
| O4 | 发布令牌一期由部署方在配置签发;只存哈希 | 明文只出现一次 |

## 6. 内容要求

- 技能格式与 `category / subject / kind` 取值表:以 `inno-agent-hub` 根 README「分类标签」「学科与用途标签」为准;发布校验按此执行
- 星图场景与精选名单 `scenarios.json`、技能包 `packs.json`:一期仍在 hub 仓库维护、随官方库导入;二期考虑迁入平台配置
- `SKILL.md` frontmatter 可带 `version`;上传不传 `version` 时以它为准

## 7. 非功能需求

| 项 | 要求 |
|---|---|
| 规模 | 用户 k 级、技能 w 级、租户百级;单实例 + PostgreSQL 全文即可,不引搜索引擎、消息队列 |
| 性能 | 列表 / 搜索 p95 < 300 ms;30 MB 包发布(校验 + 写 OSS + 入库)< 10 s;下载签 URL < 50 ms |
| 可用性 | 后端无状态,状态全在 PG / OSS;可横向加实例;定时任务加分布式锁 |
| 安全 | 三类凭证(发布令牌 / InnoAgent 服务密钥 / 管理令牌);桶私有读,临时 URL 10 分钟;禁可执行二进制,脚本类标记 `hasScripts`;不可见资源返回 404 不泄露存在性 |
| 数据 | 版本不可变、不删已发布数据;制作平台保留源文件,本平台是发布副本:PG 每日快照 + OSS 默认冗余;tar.gz 是唯一必须不丢的数据 |
| 可移植 | 只用标准 PostgreSQL 与 S3 兼容 API,不用云厂商 SDK;换云改 endpoint |
| 可观测 | 事件流水(下载 / 安装 / 浏览)、导入运行记录、健康检查 |
| 兼容 | 现有单段 `/skills/{id}` 接口保留,视为 `official/{id}`;bundle 协议不变 |

## 10. 里程碑与验收

里程碑见 `07-评审摘要.md` 第 8 节(M0 评审 → M1 后端 MVP 约 2 周 → M2 联调约 1 周 → M3 上线约 3 天)。

一期验收清单:

- [ ] 制作平台用令牌发布一个技能,列表 / 搜索 / 详情能看到,重复发布幂等,改内容不升版本被拒
- [ ] InnoAgent 带租户头看到本租户技能,匿名看不到;resolve 判断更新;拿临时地址下载成功,地址过期后失效
- [ ] 78 个存量技能导入 `official`,inno-agent 开源版改配置后可导入
- [ ] 下架一个版本后 `latest` 回退、搜索不命中、直链 410
- [ ] 搜索"备课"中文命中且 p95 < 300 ms;分面计数与结果一致
- [ ] 安装 / 卸载台账与安装人数正确
- [ ] `/healthz` 正常;PG 快照与孤儿清理任务跑过一次
